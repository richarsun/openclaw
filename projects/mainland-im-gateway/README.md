# 大陆 IM 接入层项目

## 项目定位

龙虾不再定位为主力开发客户端。主力开发入口由 Codex 承担，龙虾保留并强化为大陆 IM 接入层、企业消息路由层和组织工具桥。

这个定位下，龙虾的核心价值是把 Codex/Agent 能力接入真实工作消息场景：

- 飞书：内部生产力和运营入口，承载运营协作、文档、知识库、多维表格、技术协作等内部流程。
- 企业微信：C 端客户跟进入口，承载大规模销售触达、持续跟进、客户状态流转和销售协同。
- 微信：B 端客户点对点定制服务入口，让高净值客户使用自己最习惯的微信界面调用定制服务。

## 当前仓库关系

当前不做大规模重构，不移动运行代码，只把项目治理材料先收口到本目录。

现有代码主要分布如下：

- `src/`：OpenClaw 核心 CLI、Gateway、Agent、消息路由、模型、会话、工具系统。
- `extensions/feishu/`：飞书插件，包含消息通道以及文档、知识库、云空间、权限、多维表格等工具。
- `extensions/*`：其它通道和工具插件，如 Matrix、Teams、Zalo、LINE、Mattermost、Voice Call 等。
- `apps/`：macOS、iOS、Android 端。
- `ui/`：Web 控制台。
- `docs/channels/`：通道文档。

后续如果要治理源码边界，优先目标不是搬目录，而是把“大陆 IM 接入层”相关能力用清晰的接口和文档圈出来。

## 目标架构

```text
用户消息入口
  -> 飞书 / 企业微信 / 微信通道适配器
  -> 统一身份、权限、会话和路由层
  -> Agent 运行层（Codex / 其它模型 / 工具调用）
  -> 组织工具桥（飞书文档、多维表格、CRM、业务系统、定制服务）
  -> 回写到原聊天线程
```

关键边界：

- 通道适配器只处理平台协议、消息格式、鉴权、媒体和回写。
- 路由层处理用户身份、客户归属、会话绑定、Agent 选择、权限策略和审计。
- Agent 层只负责执行任务，不直接绑定某个 IM 平台的业务假设。
- 组织工具桥把飞书、CRM、客户服务、销售跟进、内部运营系统封装成稳定工具。

## 三条产品线

### 飞书内部运营线

目标是让内部团队在飞书里直接调度 Agent，沉淀运营流程和内部知识。

重点能力：

- 飞书消息和群聊路由稳定可用。
- 飞书文档、知识库、多维表格工具可被 Agent 安全调用。
- 内部运营任务可以从聊天触发、写入文档或多维表格、生成待办和复盘。
- 技术开发和内部协作场景保留扩展空间。

### 企业微信 C 端销售线

目标是支持面向大量 C 端客户的持续跟进。

重点能力：

- 企业微信客户、群聊、员工、标签、跟进记录等对象建模。
- 将客户消息路由到正确 Agent、销售或跟进工作流。
- 支持销售话术、客户状态更新、自动提醒、阶段推进。
- 保留人工接管、审计和风控机制。

### 微信 B 端定制服务线

目标是让 B 端客户在微信里使用定制服务，不要求客户迁移到新的工具。

重点能力：

- 微信开放接口的可行性和边界核验。
- 每个 B 端客户可绑定专属服务、权限和上下文。
- 支持点对点服务入口、服务记录、交付物回写和人工升级。
- 和内部飞书运营流程形成闭环。
